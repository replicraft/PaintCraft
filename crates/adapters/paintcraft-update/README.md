# PaintCraft signed updates

The desktop updater checks GitHub releases, streams each selected asset through minisign verification against the embedded public key, and never extracts or installs unsigned bytes. Each trusted comment is exactly `paintcraft-update VERSION FILENAME`. A signed payload cannot be relabeled as another version or platform.

Production key: `packaging/paintcraft-update-key.pub`, owned by the maintainer. `build.rs` snapshots it into OUT_DIR. Missing keys produce `SigningKeyUnconfigured`; no public placeholder is written and no test key is trusted by production. The protected `release-signing` GitHub environment supplies `UPDATE_SIGNING_KEY` and `UPDATE_SIGNING_PASSWORD` only to the signing job. No private key belongs in the repository. Key rotation requires an update signed by the old trusted key that embeds the reviewed new public key, or a manual installation.

Every desktop editor process must acquire and retain `InstallLock::acquire(&Platform::detect())` before loading documents. The stable lock file is outside the swappable application, keyed by canonical installation path. A new instance refuses while an updater holds exclusive access. Before `apply(verified, &mut lock)`, save documents and stop/join all codec and background jobs. Close the process after apply whenever `lock.requires_exit()` is true, including install errors. A failed exclusive acquisition normally restores shared ownership and returns `InstallationBusy`; if another updater wins that race, `InstallationLockLost` requires immediate exit without resuming editing. Existing old builds that do not participate in this lock require an additional process/launcher integration check or must be closed before updating; this library does not claim to discover arbitrary older editor processes.

macOS replaces the complete outer PaintCraft.app, including its nested Editor.app, launcher, codec helper and manifest. Both plists, versions, helper target and SHA-256 are checked before codesign verification and rename. Windows portable archives are flat and replace the entire matched editor/helper/manifest group with a rollback receipt; an MSI uses Windows Installer after parent exit. Linux only replaces an AppImage. Flatpak, deb, rpm, tarball, developer and unknown installations remain managed/manual and are never overwritten.

Backups remain for recovery; starting a process is not a health check. Swap failures and restart-helper launch failures roll back where the operating system permits, with errors reported if rollback fails. A later application startup failure is not automatically detected. MSI installation/relaunch and Windows filesystem behavior still require native release qualification. The update UI must never restart during active work.

This code is adapted from Relay's Apache-2.0 relay-update; LICENSE and NOTICE preserve that attribution. New dependencies are the same small HTTP/minisign/semver/ZIP components rather than replacing the app executable alone.

The publicly known `TEST-ONLY-update-key.seed` fixture is test material inherited from Relay, not a release key. The production constructor cannot select this key; release signing must reject that key ID. Tests never contact production download endpoints.
