# Independent JPEG XL regression fixtures

These tiny synthetic images were authored for PaintCraft and encoded using independent **libjxl cjxl 0.12.0**, not the selected Zune writer or jxl-rs decoder. They contain no third-party photographs or downloaded test images. `oracle.json` records exact input sample values or construction, encode flags and SHA-256 of every retained fixture. These fixture bytes may be used under PaintCraft's repository license.

The oracle identifies itself as `cjxl v0.12.0 0.12.0 [_NEON_] {AppleClang 17.0.0.17000604}`. A SHA-verified Homebrew arm64_sequoia JPEG XL bottle was extracted into `/tmp` solely for tests, with `DYLD_LIBRARY_PATH` pointing at its extracted dependencies; nothing was installed, vendored or linked into PaintCraft. Oracle bottle SHA-256: `3c193d49dacde5e78331ff37462b5ef7f09d44279801ad2df911a7a5d618c109`. The upstream source is [libjxl v0.12.0](https://github.com/libjxl/libjxl/tree/v0.12.0), BSD-3-Clause.

`rgba8`, `rgba16` and `single` use PNG RGBA input. PNG rows were authored from the integer values in `oracle.json`, encoded with standard zlib and big-endian 16-bit PNG samples. `--container=1` forces boxed fixtures. `animation` was authored as a two-frame GIF89a and independently converted; `linear` is RGB PPM input with explicit linear transfer; `icc` uses an ICC generated by LittleCMS2's `cmsCreate_sRGBProfile`, passed explicitly to cjxl. The ICC timestamp is not a reproducibility promise; fixed fixture hashes identify the exact retained input.

Mandatory tests assert actual channel values, hidden RGB, partial alpha, native 16-bit precision, dimensions, metadata loss reporting, profile refusal and animation refusal. They run offline without the oracle executable. An additional explicitly ignored test runs real djxl on freshly generated Zune output and compares every output channel; run it with `PAINTCRAFT_DJXL=<djxl path> cargo test -p paintcraft-formats --test jxl_oracle external_libjxl_decodes -- --ignored`. It has been run successfully for RGBA8 and opaque RGB16; raw evidence is under the ignored validation directory.

## Qualified adapter scope and known limits

- Decoder: static 8/16-bit integer sRGB, bare/boxed codestream, straight alpha, orientation applied. Explicit refusal for float/HDR, associated alpha, custom ICC conversion, non-alpha extra channels and animation. Container metadata is inspected with bounded box count/length and reported as discarded, rather than claimed preserved.
- Writer: lossless 2D RGBA8, including hidden RGB and partial alpha. Opaque RGBA16 uses RGB16 encoding and returns opaque alpha on decode. Single-row/column writes are explicitly refused because zune-jpegxl 0.5.2 rejects dimensions <=1. Non-opaque RGBA16 writes are explicitly refused because upstream 0.5.2 hardcodes the alpha depth to 8 bits; an independent failure exposed alpha 256 decoding as 65535.
- Resource admission: 4,194,304 pixels; 64 MiB encoded input/output; 4 MiB non-codestream container payload; 4096 boxes; checked dimensions/sample lengths. jxl-rs sample limits include row padding, while exact host limits are checked at BasicInfo before allocating adapter output.
- These bounds do **not** prove a hard peak-memory limit: jxl-rs 0.8.0 exposes no custom allocator or ICC workspace budget; its internal ICC bound is 256 MiB. No process confinement, adversarial corpus qualification or performance claim is established here. Decoder cancellation checks input, decoder-event and sequential-task boundaries. Zune cancellation checks admission and output writes; its compression loop cannot be interrupted cooperatively. Encoder threads and decoder SIMD default features are disabled for initial native/Wasm compatibility.

This is an internal adapter qualification boundary. It does not by itself enable frontend Open/Export or promise preserving Save for metadata, animations, HDR or unsupported document precision.
