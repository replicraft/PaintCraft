# EXR bounded preflight qualification

Ten owned fixture files were produced and reopened by official OpenEXR 3.5.2 in an isolated Python 3.14 environment with NumPy 2.4.3. `oracle.py` contains the complete source pixels and writes the `.exr`, interleaved RGB/RGBA float32 little-endian reference bytes, and hashed `manifest.json`. The Rust EXR crate does not participate in this oracle. The bounded preflight does not decode samples. The optional private adapter below compares decoded samples against these independent references.

Run `python oracle.py` only in a private environment containing the pinned packages. OpenEXR's Python writer mutates the supplied channel dictionary into Channel objects, so the oracle preserves independent array copies before writing and compares reopened samples to those copies. The first harness attempt exposed that Python API behavior; no product decoder was involved.

The private initial profile is version-2, single-part, non-deep, scanline RGB or RGBA. Channels are exactly top-level R/G/B with optional A, ordered as required by the format, HALF or FLOAT (mixed types also representable), and full-rate 1x1 sampling. UINT, extra channels/groups, tiled/multipart/deep data, long names, and other compression families are refused. NONE, RLE, ZIPS and ZIP compression declarations and their bounded chunk geometry are represented; preflight does not prove a compressed payload decodes. Both zero and signed nonzero origins work when data and display windows match. Origin is retained verbatim; a later conversion must explicitly report coordinate normalization rather than silently dropping source placement. Differing windows require an explicit canvas policy and remain refused.

Dimensions use signed 64-bit differences before admission: sides at most 65,536, at most 4,194,304 pixels, at most 64 MiB source and 64 KiB header, at most 128 attributes, and short names. Offset tables and chunk headers must agree with admitted geometry, signed source row origin, channel byte widths and increasing line order. Every chunk is wholly in bounds; intervals cannot overlap, leave gaps, point into the header/table or leave trailing unqualified content. This is bounded container admission, not a decompressor, process heap limit or physical RSS guarantee. Source storage remains caller-admitted. Callback cancellation during header/table/chunk/hash work publishes no inspection.

Exact canonical float32 chromaticities recognize only the precision policy's known nominal spaces. Nearby values are retained, never snapped to a gamut. The explicit `colorInteropID=lin_rec709_scene` is recognized only when any chromaticities agree. Missing, unfamiliar or conflicting color metadata remains unresolved and requires the precision policy's explicit source-space assignment; unlabelled EXR never silently becomes Rec.709. All original bounded attributes remain borrowed from the sealed SHA-bound source, including unknown provenance, for later receipt/loss decisions. Duplicate attributes and channel names are refused.

Alpha follows the OpenEXR conventional premultiplied meaning; source samples, including additive RGB at alpha zero, are not changed by inspection. The existing precision policy separately requires explicit flattening or refusal for additive alpha-zero color, supports deliberate alpha-convention override, and refuses nonfinite or out-of-range alpha. This preflight does not claim sample validity or silently unassociate, clip, tone-map or quantize samples.

## Optional selected decoder qualification

`exr-codec` enables pinned `exr = 1.74.2` with default features disabled. The resolved EXR node has no features and no Rayon dependency. Decoding additionally uses explicit `non_parallel()` and pedantic validation. The published crate SHA256 is `711fe42c9964295e01ee3fba3f9fe0e1d24b98886950d68efe81b1c76e21adf3`. Exact audited attribute/header/reader/compression sources and their hashes are preserved in ignored `docs/validation/exr-policy-2026-10-26/decoder-4d44586d-69be-49ee-8001-c573517d717e/`.

Only the original immutable source retained by a sealed `Inspection` can reach this decoder. Every selected `AttributeValue::read` branch is audited before invocation, independent of attribute name: fixed scalar/vector lengths, nested preview dimensions, string-vector extents, opaque byte type-hint lengths, and integer-box arithmetic are checked. Additional typed channel lists at unknown names are explicitly unqualified rather than escaping the four-channel bound. Original bounded attributes are retained, never stripped. This codec-specific validation can refuse metadata that structural inspection safely retains. Integer boxes touching i32::MAX or exceeding the selected backend's i32 intermediate range remain a visible decoder refusal, without modifying source coordinates.

Output is exactly interleaved RGB or RGBA float32 in R/G/B/A order, irrespective of on-disk alphabetical channel order. HALF values convert exactly to float32; FLOAT values, including negative/nonfinite color and invalid alpha in the special fixture, remain unchanged for the later explicit precision policy to accept or refuse. The mixed fixture combines HALF R/A with FLOAT G/B under ZIP. Signed source origin, alpha presence and original source SHA remain attached to the result; no source-space assignment, clipping, tone mapping, alpha unassociation or coordinate rewrite happens here.

The output buffer is fallibly reserved before the backend's image-constructor callback consumes it. Logical admission retains output plus a conservative 4 MiB metadata/inventory allowance and eight times the largest admitted decoded block. Metadata and codec block buffers drop before handoff. The selected backend retains an interleave Vec in thread-local storage, so each private decode uses one fallibly spawned scoped thread, joins it, and only then reduces the retained charge to the float buffer's actual capacity. A thread-local destructor probe verifies the scratch charge is still held through thread exit on success, cancellation and panic. Spawn failure maps to ResourceLimit, panic to CodecFailed, and callback cancellation remains OperationCancelled. No new thread pool is introduced.

This is synchronous private qualification, not hostile-input isolation. Cancellation checks occur before/after decode and at source reads/seeks; they do not interrupt a decompressor CPU loop. Joining is not killable cancellation or a hard deadline. Thread stacks, allocator overhead and physical RSS are excluded from logical byte accounting. A future process helper still needs its full fixed heap ceiling and lifecycle budget; no helper protocol or public route is changed here.

Validation: `cargo test -p paintcraft-formats --features exr-codec --lib exr:: --offline --locked` compares all ten official fixture outputs bit-for-bit against the independently reopened RGB/RGBA references. It also verifies source immutability/binding, output retention/release, denied allocation, callback cancellation, corrupt compressed payload failure, exhaustive typed metadata refusal at unfamiliar names, and charge retention through thread exit. Default feature behavior remains unchanged.
