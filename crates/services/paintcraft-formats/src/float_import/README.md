# Private float import preparation

`float_import` composes the existing bounded HDR/EXR inspectors and optional decoders with the existing `precision::Binding` and conversion math. `prepare_hdr` exists only with `hdr-codec`; `prepare_exr` only with `exr-codec`. The optional V7 worker and native parent integration are locally qualified. The helper enables both decoder features by default after consumer qualification; frontend admission remains a separate policy.

Preparation derives source SHA, geometry, signed origin, pixel aspect, original color evidence, channel types and alpha convention from the inspected source. It creates an immutable policy Binding before decode, so unresolved EXR color requires an explicit source assignment. The sealed assessment retains the exact bounded original header bytes, settings, output hash, actual conversion statistics and every required loss. A cached digest binds the complete assessment, including its raw header and output hash. No unrelated decoded buffer or replacement metadata can be supplied by a caller.

`Prepared::preview_rgba` is explicitly a preview. Consuming `approve(expected_assessment_digest, allowed_losses)` checks the exact assessment/settings digest, rejects unknown or missing loss consent, and returns `Approved`. A consumer of this standalone decoder path must require that approved result and independently validate the captured source file/editor owner. This digest does not prove filesystem freshness, source-path identity, active tab, unsaved drafts or publication permission. Those remain native Job/frontend responsibilities; preparation performs no filesystem writes or editor/document mutation.

The assessment's raw header is retained for the receipt, not preserved in a PCND document. Its receipt explicitly marks `metadata_preserved_in_document=false`. Detached JSON receipt storage belongs to the caller's admission. Format-specific limitations supplement the existing precision policy's actual losses:

- `hdr-metadata-not-retained`: original HDR calibration/comments/unknown records, or EXR descriptive/unknown attributes and nondefault screen-window metadata are not adopted into the destination document. Raw values remain in this assessment. Encoding structure and color/geometry already represented by the explicit conversion are distinguished from additional metadata.
- `hdr-pixel-aspect-normalized`: nonunit source pixel aspect becomes square destination pixels without resampling. The exact original aspect is retained as float64 bits; this is a declared physical-display change, not a hidden rescale.
- `exr-origin-normalized`: a nonzero signed source origin becomes destination origin [0, 0]. Pixels and their relative positions remain unchanged; original coordinates remain in the receipt.
- `hdr-linear-alpha-compositing-changed`: retained source alpha contains values strictly between 0 and 1. The receipt names the destination's encoded-sRGB u8 source-over blending and binds the actual count. This can differ from scene-linear source compositing independently of alpha quantization. Opaque sources and explicitly flattened outputs do not receive this limitation.
- `hdr-rgbe-lower-edge-representative`: explicit RGBE reconstruction choice. Exponent zero means black; positive exponent E uses mantissa M times 2^(E-136). This is the selected lower-edge representative, not a claim that it equals original Radiance's midpoint representative.

Radiance samples remain as stored: EXPOSURE and COLORCORR are neither applied a second time nor undone. The original ordered records and calibration values survive in the raw source header receipt. The nominal Radiance equal-energy color space is converted by the existing qualified precision policy; RGB channel names alone never imply sRGB. EXR samples remain as-stored floats until that same policy applies the chosen source-space, alpha, exposure, negative-value and curve settings.

Alpha convention defaults to OpenEXR's premultiplied interpretation and can be explicitly overridden, with consent. Additive color at zero alpha requires explicit linear-light flattening or refusal; it is never silently discarded. Nonfinite color or alpha and alpha outside [0, 1] are refused. Clip and Reinhard-per-channel remain named choices, so the latter's ordinary-white mapping is never substituted silently. This module implements no duplicate compositor, color transform or tone-mapping engine.

Standalone decoder preparation uses the same SharedBudget for preflight metadata scratch, source receipt, decoder floats and converted RGBA. A 3 MiB transient metadata declaration covers the bounded preflight offset/interval inventories (up to 65,536 entries), original-header processing and internal receipt/digest construction. A separate declaration covers the retained source header's actual capacity plus bounded descriptor/loss storage. The decoded float buffer remains charged while RGBA conversion allocates and runs; both coexist under that one budget. On return, decoder floats/scratch and transient metadata release, leaving only RGBA plus retained assessment metadata. Approved results retain those accounts until drop. Cancellation, policy refusal or failed consent releases all private storage.

These are logical declarations, not heap/physical RSS limits. Source input storage remains caller-admitted. EXR's one-shot scoped decoder thread joins before its scratch charge releases; join is not killable cancellation or a hard deadline. The native process path described below supplies supervised kill/reap, protocol/owner/source guards and resident document preparation. Public consumer admission remains a separate requirement.

Independent end-to-end expected pixels live in `tests/float-import-fixtures`. Their generator reads the existing official OpenEXR-reopened float references and independent Radiance lower-edge references, then uses the separately qualified Decimal100/NumPy policy oracle. It never invokes the selected Rust decoder or Rust conversion implementation. Tests cover both curves, exposure, assignments, calibration provenance, signed origins, both formats' pixel aspect, additive-alpha refusal/flattening, explicit straight-alpha override, nonfinite refusal, exact consent, and cancellation while float and RGBA allocations coexist.

The compositing limitation is confirmed against the actual editor `Rgba::source_over` API. Scene-linear premultiplied RGB .25 with alpha .5 becomes straight sRGB [188,188,188] with A128 when transparency is retained; the current encoded-u8 source-over compositor produces [94,94,94] over black. Explicit scene-linear flattening over black instead produces [137,137,137] with A255 and no retained-alpha compositing limitation. The generic precision conversion and editor compositor are unchanged. The assessment reports this difference instead of implying preservation of source compositing.

Historical initial-preparation validation: five targeted float-import tests covered all seventeen independent reference cases and the actual compositor counterexample. `cargo test -p paintcraft-formats --features exr-codec,hdr-codec --lib float_import:: --offline --locked` and the corresponding `cargo clippy --lib --tests -- -D warnings` pass, as do scoped Rust formatting and diff checks. The independent oracle source/golden hashes and the exact-once entrypoint guard are checked.

## Parent source plan and finite payloads

Pure `plan_hdr` / `plan_exr`, `SourcePlan`, `WorkerAssessment` and `wire` are available without either decoder feature. Planning runs bounded structural inspection and creates the exact Binding/header/source-loss description, never floating-point decoding. The initial private parent profile is limited to 16 MiB source and 1,048,576 pixels; this narrower worker prerequisite does not replace the standalone decoder qualification bounds or define permanent format support. Actual `prepare_hdr` / `prepare_exr` remain feature-gated.

`wire::encode_settings` and `decode_settings` use exactly 32 bytes, with no implicit child defaults:

| Offsets | Meaning |
| --- | --- |
| 0..8 | `PCFLTS01` magic |
| 8..10 | big-endian schema 1 |
| 10, 11 | Clip/Reinhard and Reject/ClipToBlack finite tags |
| 12, 13, 14 | Preserve/Flatten, optional source space and optional alpha assignment |
| 15 | zero reserved byte |
| 16..20 | signed big-endian exposure milli-EV, -16000..16000 |
| 20..23 | flatten backdrop RGB; all zero for Preserve |
| 23..32 | zero reserved bytes |

A `Report` encodes exactly 96 bytes: `PCFLTR01` at 0..8, schema1 at 8..10, zero reserved bytes at 10..16, assessment digest at 16..48, five big-endian u64 statistics at 48..88 in Statistics declaration order, and retained original partial-alpha count at 88..96. Unknown tags, versions, reserved/inactive values and wrong byte lengths refuse. The opt-in V7 helper uses these payloads for explicit HDR/EXR operations; older helpers refuse those operations.

`SourcePlan::accept_report` accepts only the expected dimensions and exact RGBA extent. It bounds RGB statistics by three times the source pixel count, alpha statistics by pixel count, checks policy-dependent zero values and opaque output, then derives required losses with the same classifier used by actual conversion. The parent constructs the raw source metadata and canonical assessment itself and compares the child's digest. No worker JSON or arbitrary worker loss list can replace those source facts. Original float statistics are bounded semantic reports from the qualified decoder, not independently decoded proofs on the host.

The source partial-alpha count is not the output count of A1..254: values near zero or one can quantize to A0 or A255. The validator requires output-partial count no greater than retained source-partial count, and alpha quantization count no greater than retained source-partial count. Opaque/flattened output requires both zero. Additive-zero-alpha statistics are permitted only for effective premultiplied alpha with explicit flattening. Tests cover near-endpoint alpha and impossible semantic reports even when a matching canonical digest is forged.

The accepted WorkerAssessment retains metadata admission; the matching RGBA storage and source/file/editor freshness guards remain the caller's responsibility. Reconstruction declares transient metadata/digest scratch before allocating receipts. The default codec features and PCDEC002 outer header remain unchanged; float operations use the separately qualified V7 helper contract.

Current source-plan/payload validation: nine targeted float-import tests pass, including reconstruction against the seventeen independent fixtures, finite settings/report checks, matching-digest semantic forgeries and near-zero/near-one alpha. Three precision-policy tests pass after extracting the shared loss classifier. Strict Clippy passes with both decoder features and without either feature; default, HDR-only and EXR-only checks pass. This remains a qualified-worker reconstruction seam: the host bounds and binds reported original-float statistics without independently decoding them. These foundational tests are supplemented by the actual optional worker and native-parent proof below; the original private foundation left default-helper and public-gate changes to later qualification.


## Native worker preparation and adoption

The optional `paintcraft-codec-worker` `float-codecs` build uses the exact V7 build record and profile. `codec_worker::native::Job::prepare_float` requires explicit `precision::Settings`, independent resident and metadata budgets, an existing admitted `ResourceLease`, cancellation/current-owner checks, a required frontend-admission callback, and a bounded launch/reap supervisor. Generic `Job::consume` and ordinary preparation refuse float jobs; no decoder-error fallback selects another profile.

The parent captures the source identity into bounded raw bytes, checks the expected raw SHA-256, and derives `plan_hdr` or `plan_exr` from those same bytes. `codec_worker::float::capture` constructs the canonical Settings32+raw envelope. The raw file hash binds source freshness and the assessment; the distinct envelope hash binds IPC. The parent selects the exact V7 contract before binary integrity verification. It validates Report96 and RGBA through `SourcePlan::accept_report`, then imports through existing admitted raster/document services. Prepared decoder identifiers distinguish `native-hdr-sdr8-worker-v1` and `native-exr-sdr8-worker-v1` from the helper build profile.

`PreparedImport::adopt_float` requires the expected assessment digest and every actual reported loss. Generic `adopt` and `adopt_with_losses` refuse float results. Adoption repeats cancellation, current-owner and captured-source checks before returning an adopted document for host publication. Failures release the quarantined document without changing the host session. `WorkerAssessment` and its metadata account remain alive through preparation and the adopted result, including shared receipt references; document tiles retain their ordinary resident leases. Detached receipt JSON still requires caller admission.

Logical transient admission covers the child's 256 MiB allowance once, raw source up to 16 MiB, a distinct envelope up to 16 MiB+32 bytes, bounded response and IO. Metadata separately covers the existing 3 MiB scratch declaration and retained header. Before launch, the parent reserves exactly `ceil(width/256) * ceil(height/256) * TILE_BYTES` using checked arithmetic and `Admission::with_reserved_residency`. Tiles are not charged again as transient scratch. The maximum geometry is independently derived over sides up to 65,536 and at most 1,048,576 pixels, including extreme thin images. These are logical admission bounds, not RSS guarantees.

Actual local native-parent qualification uses a copied installation and the immutable opt-in V7 helper, without replacing the default V6 helper. `codec_worker::native::float::tests::copied_installed_v7_float_job` passed twelve independent exact RGBA and PCND round-trip cases and five expected source/conversion refusals. It also passed raw-versus-envelope hash checks; digest, missing-loss and generic-adoption refusals; source, owner and cancellation changes after the child and before adoption; exact prelaunch residency; and retained metadata lifetime after document drop. The copied process test completed in 152.55 seconds on the local qualification host. The helper SHA-256 was `78b8541fca14863928ef6934f176b713045c82891f18a5662a0ace7aa18da4c7`.

The parent proof runs with `PAINTCRAFT_V7_HELPER` set to the qualified helper path and `cargo test -p paintcraft-formats codec_worker::native::float::tests::copied_installed_v7_float_job --lib -- --ignored --exact --nocapture`. Default-feature codec regressions passed 22 tests with four installed fixtures ignored. Strict `cargo clippy -p paintcraft-formats --lib --tests -- -D warnings`, scoped formatting and diff checks passed. This is local process qualification, not a cross-platform release or an independent host decode of original-float statistics.


## Explicit legacy compatibility with V7

Legacy native Jobs accept only enumerated helper contracts: the base JXL/JXR/HEIF paths accept V4/V5/V6/V7, identity AVIF accepts V5/V6/V7, and SDR AVIF accepts V6/V7. Float preparation remains V7-only. The bounded manifest selects one contract before executable verification; unknown profiles, changed hashes, mismatched variants or forged older-profile manifests fail without retrying another contract. The final V7 descriptor supersedes the historical private V7 descriptor; format gates remain separately reviewed. CLI AVIF capability metadata lists the same finite accepted profiles while preserving the historical minimum-profile field and runtime installation preflight requirement.

The local copied-V7 legacy qualifier passed all six existing codec operations: native HEIF gray samples plus five document-adoption paths (JXL, JXR, HEIF sRGB, identity AVIF and SDR AVIF). The document paths matched independent exact pixels and PCND round trips, exact source-specific losses, unchanged source bytes, resident lease retention/release, and source/owner changes after the child. Four unknown/forged manifest mutations across all six codecs refused before launch. `codec_worker::native::compatibility_tests::copied_v7_installation_keeps_legacy_native_jobs_compatible` completed in 25.06 seconds using the same immutable helper hash above, with no shared debug-helper replacement. Focused platform tests also validate four exact choices over all six synthetic release headers and reject duplicate, mixed-version/protocol/heap, unknown, corrupted and forged contracts. Synthetic target headers are verifier coverage, not native execution on those platforms.


Final distribution uses the nonprivate V7 profile and `QUALIFIED_FLOAT_IMPORT_VARIANTS` with seven ordered variants. The immutable record, protocol, schema and numeric policy are unchanged. Historical private manifests with five variants are not accepted as final manifests. Final V7 notice requirements are profile-dependent and add the versioned HDR/EXR aggregate without changing exact legacy V4/V5/V6 payloads. The earlier proof/hash/timings above remain historical private-snapshot evidence; final-descriptor process and installation results are recorded separately.

The final nonprivate descriptor was separately exercised against optimized helper `24a014c300a3b8050b50afa4e71d1391c2949446b12bae7583a2ca48017ce29d`, built through the canonical locked source installer path and packaged/installed into an owned local prefix. This is local Apple-silicon execution; it does not claim native execution on the other release platforms or OS GUI installation/file-event behavior.
