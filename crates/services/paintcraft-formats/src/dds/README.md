# Internal DDS single-surface adapter

`dds` 0.2.0 is used directly with default features disabled; no Rayon worker pool or native codec is introduced. This adapter is not yet a frontend capability registration.

Admitted profiles are packed RGBA8/BGRA8 and BC1/BC2/BC3 UNORM, including the corresponding explicit DX10 sRGB formats. Input must contain exactly one 2D texture and one mip level. Arrays, cubemaps, volumes, 1D resources, typeless DXGI formats, deep/float data, premultiplied/custom alpha and padded uncompressed row pitch are refused. Unflagged raw mip counts greater than one are also refused rather than normalized silently.

The neutral DTO retains source encoding, transfer and alpha interpretation. Legacy transfer and alpha remain unspecified; DX10 UNORM and sRGB are distinguished without transforming samples. Straight-alpha and hidden RGB bytes are retained. An explicit DX10 opaque-alpha declaration produces alpha 255, since those stored alpha bytes are not meaningful opacity. A separate exact uncompressed RGBA8 writer requires an explicit Linear or sRGB declaration and emits DX10 with straight alpha. It does not convert source samples or encode BC compression. No preserving-Save claim extends to texture workflows or unsupported metadata.

Admission happens before output allocation: source <=64 MiB, output <=64 MiB, <=4,194,304 pixels, dimensions <=65,536, and decoder workspace <=8 MiB via `DecodeOptions::memory_limit`. The exact encoded body size must match the single-surface layout. Decoding must consume that complete body and finish the surface iterator; trailing bytes or truncated surfaces are errors. Source bytes remain borrowed. Cancellation runs during input reads and before/after codec work; the original canonical error is restored. Cancellation uses a non-retryable IO error internally so `read_exact` cannot retry forever.

The mandatory regression vectors are hand-authored from [Microsoft DDS_HEADER](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-header), [DDS_HEADER_DXT10](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dds-header-dxt10) and [BC compression definitions](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-block-compression). They independently specify RGBA/BGRA masks, hidden colors, partial alpha, RGB565 endpoints, BC1 selectors/transparency, BC2 explicit alpha nibbles and BC3 alpha endpoints. No codec-generated file is its own expected pixel oracle. Small cropped BC edges still consume a complete physical block. Writer tests independently assert every structural field, physical RGBA payload bytes, hidden colors, declared transfer, cancellation, and 1x1 support. Additional tests cover strict headers, every short-file truncation, trailing bytes, mip/array/cube/deep/typeless refusals, geometry limits and cancellation.

Qualification remains scoped to these vectors. No original-application corpus, texture workflow, broad compression fidelity benchmark or hard process-level memory sandbox has been established. Upstream API reference: [dds 0.2.0](https://docs.rs/dds/0.2.0/dds/).
